# Перенос проверки на сервер (FastAPI)

## Что есть сейчас (этап 1)

- Игрок пишет в базу только **журнал своих действий** (`players/{uid}.actions`: задание, взнос, открытие бизнеса, улучшение, сбор выручки, оценка). Полей «баланс», «репутация», «бизнес» в записи больше нет.
- Баланс, репутацию, взносы, бизнесы и сам город каждый клиент вычисляет функцией `replay()` (`frontend/src/game/sim.ts`). Она проигрывает историю по дням и применяет действия всех игроков в порядке времени. Каждое действие проверяется по правилам. Действие, которое правила нарушает, пропускается и пишется в `console.warn`. Все клиенты видят одно и то же.
- Награды берутся из каталога, а не из записи: за задание платится сумма из `DAILY_TASKS`, за сбор выручки — то, что бизнес реально накопил по формуле, а не то, что прислал клиент.
- Стартовые балансы (перенос старых сохранений, перезапуск города) пишет только основатель в `game/opening`.
- «День заданий» один для всех: полночь по Ташкенту (UTC+5). Время клиент берёт с сервера (аренда документа в базе возвращает время истечения по часам сервера), а при недоступности — с устройства.

## Что это закрывает и что нет

| Атака | Сейчас |
|---|---|
| Записать себе баланс, бизнес, взносы | закрыто: такие поля не читаются |
| Поддельный взнос больше баланса | закрыто: правило «взнос ≤ баланса» |
| Повторная награда за задание | закрыто: одно задание каждого вида за день |
| Перевести дату на телефоне вперёд | закрыто: действия дальше чем на 10 минут вперёд от серверного времени не считаются |
| Собрать выручку чаще или больше | закрыто: сумма считается по формуле |
| Задним числом дописать задания за прошлые дни | **частично**: время действия ставит клиент. Журнал можно только дописывать (запись раньше предыдущей пропускается), но человек с консолью может один раз дописать задания за дни, когда не играл. Максимум, что он получит, — столько же, сколько честный игрок, игравший каждый день. |
| Выдумать, что задание выполнено (не играя мини-игру) | **не закрыто**: проверить мини-игру можно только на сервере |

## Что сделать на сервере

1. **API.** FastAPI-сервис с одним методом `POST /actions` (тело — одно действие). Сервер:
   - ставит время действия сам (`t = server_now`), клиентское время игнорирует;
   - прогоняет действие через ту же функцию правил (портировать `replay()` на Python или запускать TypeScript-версию в Node-воркере);
   - если правило нарушено — `409` с причиной, если нет — дописывает действие в журнал игрока.
2. **База.** Журналы пишет только сервер: в правилах базы `players/{self}` поставить `write: "owner"` (или вынести журналы в серверную БД). Клиент только читает.
3. **Мини-игры.** Проводка: сервер выдаёт задание с зерном перемешивания и принимает ответ (порядок проводов), проверяя его. Доставка и обход: сервер принимает нажатие на здание вместе с текущей позицией камеры, проверяет, что здание видно и что между нажатиями прошло правдоподобное время.
4. **Контрольные точки.** Сервер хранит итог проигрывания каждые 100 игровых дней и отдаёт клиентам готовое состояние, чтобы телефон не пересчитывал историю.
5. **Миграция.** Журналы переносятся как есть; `game/opening` остаётся стартовой точкой.
