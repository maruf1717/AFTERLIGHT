# ЗАДАНИЕ: исправить все проблемы AFTERLIGHT по итогам аудита

Ты работаешь в репозитории `maruf1717/AFTERLIGHT` (папка `frontend/`, React + TypeScript + Vite + three.js / react-three-fiber + zustand). Это браузерная игра про город на острове. Владелец проекта не программист в деталях: он проверяет результат с телефона, поэтому мобильная версия — главная.

Ниже все проблемы, найденные при ручном прохождении игры (телефон 390×844 и 360×640, телефон боком 844×390, планшет 820×1180, компьютер 1440×900) и при чтении кода. Коды задач (C1, M3, V5…) совпадают с отчётом аудита (`AFTERLIGHT_audit.md`).

## Общие правила (обязательно)

1. Работай **по этапам, строго по порядку**. После каждого этапа: `npm run build` без ошибок, `npm run test` зелёный, отдельный коммит с понятным сообщением на русском `Этап N: …`.
2. **Не удаляй работающие механики.** Задания, проекты, бизнес, рейтинг, админка, творческие работы, ночь, эконом-графика должны продолжать работать.
3. **Сохрани старые данные.** Сохранения в `localStorage` (`afterlight:game:v1`) и записи в общей базе должны открываться после твоих изменений. Если меняешь формат, напиши миграцию v1 → v2 и тест на неё.
4. Все тексты для игрока на русском, короткие, без жаргона, в стиле существующих. Никаких обещаний того, чего нет в игре.
5. Мобильная версия первична: каждое изменение интерфейса проверяй на 360×640, 390×844 и 844×390 (телефон боком).
6. Числа баланса держи в `game/catalog.ts`, а не в компонентах.
7. Если задача требует решения, которое ты не можешь принять сам (например, внешний сервер), сделай подготовку, опиши в `docs/DECISIONS.md`, что осталось, и иди дальше.
8. В конце каждого этапа допиши в `docs/CHANGELOG.md`, что сделано и как это проверить.

## ЭТАП 1. Критичное: честность экономики

- **C1.** Журнал действий игрока `actions: { type, at, payload }[]`; баланс, репутация, взносы и бизнес вычисляются чистой функцией `deriveState(actions, config, city)` с правилами (не больше 5 заданий одного вида за день заданий, взнос не больше баланса и `dailyDonationLimit`, один бизнес, выручка не больше `pendingIncome`, награды за творчество только из `reviews` владельца). Нарушающие действия игнорируются (`console.warn`). `docs/SERVER_PLAN.md` — перенос на FastAPI. Миграция: `legacy_balance` для старых игроков. Тесты: поддельный взнос 50 000 при балансе 300 не увеличивает `funded`; 10 «wires» в день дают награду один раз.
- **C2.** День заданий от `config.startedAt`, зона `Asia/Tashkent`, время сервера если доступно; действия больше чем на 10 минут в будущем игнорируются. Тест: действия «завтра» не засчитываются.
- **G15.** В общей базе `soloMode: false`, локально `true`.
- **G14.** Перезапуск возвращает Искры (`restart_refund`): взносы, открытие бизнеса, улучшения. Тест.

## ЭТАП 2. Серьёзные ошибки

- **M1.** Пересчёт `happiness`, `inflow`, `outflow` после финального `evaluate(now)`. Тест.
- **M2.** Вариант `phone` = `(max-height: 500px), (pointer: coarse) and (max-width: 1024px)`; горизонтальная раскладка: вкладки слева колонкой, панель справа на всю высоту.
- **M3.** `onBuildingOpened(id, source: 'map' | 'pager' | 'directory')`, доставка и обход только `map`.
- **M4 + U3.** Уникальные имена зданий («ЖК «Плющ», ул. Медная, 12»); «Показать дом» с пульсирующей подсветкой и меткой «Посылка сюда». Тест на уникальность.
- **M5.** Границы полей админки, ошибка под полем, та же проверка в `adminSaveConfig`.
- **m1.** `fmtSigned()` в `ui/game/common.tsx`.
- **M6.** Нельзя списать больше баланса игрока.
- **M7.** `dayPeriods: { from, minutes }[]`, `dayIndexAt(t, cfg)`. Тест.
- **M8 + M9.** «Только целое число», «Вложить» неактивна при ≤ 0, подтверждение больших взносов.
- **M10.** Статусы и занятость из симуляции.
- **M11.** Общий обработчик Esc.
- **M12.** Окно «Проекты» не закрывается после взноса; камера только при первом взносе (кнопка «Посмотреть стройку») и при завершении.
